# 仿真实验工作流

## 目标

仿真器不应只是一张实时画面。场景定义、执行、验证、留档、指标比较都必须能在没有 Godot 的情况下完成；Godot 只是实验的交互查看器。

## 实验计划

实验计划位于 `simulator/scenarios/`，格式由 `tools/schema/experiment_plan.schema.json` 描述。计划包含版本、实验名称和多个 case；每个 case 有场景参数及一个或多个显式随机种子。参数缺省值与 `nncar_sim` CLI 的历史默认值一致，执行器会把解析后的完整参数写入每个 run 的 `parameters.json`。

```json
{
  "schema_version": "1.0.0",
  "name": "controller-regression",
  "cases": [
    {
      "name": "s-curve",
      "seeds": [23, 42],
      "scenario": {
        "duration_s": 8,
        "v_desired_mps": 0.8,
        "amp_m": 0.08,
        "wavelength_m": 3.0
      }
    }
  ]
}
```

## 命令行流程

```bash
python3 tools/python/simctl.py validate simulator/scenarios/regression_suite.json
python3 tools/python/simctl.py run simulator/scenarios/regression_suite.json
```

运行器负责调用 C `nncar_sim`，Godot 不是批处理依赖。默认二进制不存在时，运行器配置并构建 `build/nncar_sim`；也可用 `--sim-bin` 指定已有可执行文件，`--out` 指定实验归档根目录。

```text
simulator/runs/experiments/<plan>-<UTC timestamp>/
├── plan.json                 # 规范化参数计划
├── plan.source.json          # 原始输入字节
├── summary.json              # 运行状态、Git 版本、哈希、指标汇总
└── runs/<case>/seed-<seed>/
    ├── parameters.json
    ├── run.csv
    ├── run.manifest.json
    ├── stdout.log
    └── stderr.log
```

每个产出的 CSV 和 manifest 都通过现有 schema/语义验证。汇总指标包括横向/航向误差峰值与 RMS、平均速度、PWM 峰值、失线比例和安全故障样本数。失败的 case 也会保留日志和错误信息；总体状态标为 `failed`，不会覆盖先前实验。

## 系统边界与后续

- C 控制栈和当前简化 plant 仍是被测对象及数值真值；实验执行器只负责编排，不重新实现动力学。
- 固定随机种子、计划源文件、规范化参数、CSV 和 manifest 构成可复现实验记录。
- 当前 plant 仍是假设性的无侧滑模型；实验可比较控制器行为，但不能替代实车校准。
- 下一阶段可在同一计划/运行记录契约上增加 Godot 场景选择、历史 run 浏览和 A/B 指标对比。
- 只有当轮地接触、坡面、碰撞或侧滑影响验收结论时，才增加 MuJoCo/Webots 等物理后端；实验计划和产物契约不应绑定某个渲染界面。
