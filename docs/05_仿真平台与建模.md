# 仿真平台与建模约定

## 1. 平台边界

```text
configs/vehicle_default.json
          ↓ 生成固定尺寸 C profile
C11 controller + deterministic plant
          ↓ CSV + run manifest
Godot 3D replay / sensor inspection

vehicle profile ──> Blender build script ──> .blend source + Godot .glb
```

- **C 是控制与数值结果的唯一真值。** Godot 不复写 LineFollower、MotorController 或 Safety，也不自行积分小车运动。
- **Blender 负责可视模型。** 几何尽可能取自车辆 profile；尚未测量的外壳尺寸和辅助轮只作可视占位，不参与动力学。
- **CSV 是仿真与检查工具之间的契约。** 每次运行记录 scenario、seed、车辆几何、模型参数及逐路传感器的 value/exist/valid。
- 目前是快速、确定性的控制器仿真，不是通过了实车校核的 digital twin。Profile 中 `verified=false` 的机械参数不能用于安全证明。

## 2. 坐标与车辆几何

控制器/仿真坐标统一为车头 `+X`、车左 `+Y`、逆时针 yaw 为正。Godot 世界坐标转换为：

```text
Godot position = (-sim_y, height, -sim_x)
Godot yaw      = sim_theta
```

当前默认实例参数（来自 `configs/vehicle_default.json`）：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 轮半径 `r` | 0.0325 m | profile 值，待实车测量确认 |
| 驱动轮距 `L` | 0.150 m | 两驱动轮接地点间距，待实车测量确认 |
| 灰度通道数 | 8 / 最多 16 | 不存在的槽位写 `exist=0, valid=0` |
| 传感器横向位置 | +52.5 到 −52.5 mm，间隔 15 mm | 正值为车左；数组按左至右排序 |
| 灰度阵列前置距离 | 0.090 m | 相对驱动轴/控制参考点 |
| 黑线宽度 | 0.020 m | 当前合成传感器的建模参数 |

Blender 车体源文件为 `assets_source/nncar_vehicle.blend`，由
`simulator/assets/build_vehicle.py` 从车辆 profile 生成。GLB 根节点原点在驱动轴中心的地面投影处；轮心高为 `r`，左右轮心在 `±L/2`，传感器横向位置和前置距离与 profile 相同。当前车壳长度 0.19 m、轮胎宽度 0.018 m、后球轮是**视觉假设**；确认实物尺寸后应把它们加入 profile，而非从渲染模型反推控制参数。

重建模型：

```bash
blender --background --python simulator/assets/build_vehicle.py
```

`.blend` 保存在 Godot 工程目录外，避免 Godot 再次尝试导入 `.blend`；生成的 `.glb` 放在 `simulator/assets/`。

## 3. 当前 C plant 数学模型

### 3.1 电机和执行器

每个驱动轮独立计算。`u` 是安全层后的归一化 PWM，`db` 是 profile 死区：

```text
D(u) = sign(u) · max(0, (|u| − db) / (1 − db))
τ    = Kτ · D(u) · Vrail/Vnom − b·ω
ω[k+1] = ω[k] + (τ/I)·dt
```

可选库仑静摩擦 `motor_stiction_nm` 在起转和运动时分别按 breakaway/Coulomb 摩擦处理。`I`、`b`、`Kτ` 是**电机轴等效仿真参数**，并非从外形尺寸推导。初始值：

| 参数 | 默认值 | 当前来源/状态 |
|---|---:|---|
| `I` | `2e-5 kg·m²` | 起始仿真假设，需用阶跃数据拟合 |
| `b` | `4e-4 N·m·s/rad` | 起始仿真假设，需用阶跃数据拟合 |
| `Kτ` | `b·v_max/r = 0.01846 N·m` | 按无负载目标轮速构造的等效值 |
| `motor_stiction_nm` | `0` | 默认关闭，便于保持历史基线 |
| 固定积分周期 | `dt=0.002 s` | 500 Hz，显式 Euler |

上述 `I/b=0.05 s`，当前步长约为该时间常数的 1/25。CLI 可以覆盖模型参数；`--stiction-nm`、`--motor-inertia`、`--motor-damping`、`--motor-torque-gain` 的值都写入 manifest。未辨识前，这些值只应作为敏感度实验参数。

### 3.2 差速底盘与轨道

轮速到车体运动使用无侧滑差速运动学：

```text
vL = r·ωL                 vR = r·ωR
v  = (vL + vR) / 2       yaw_rate = (vR − vL) / L
x[k+1]     = x[k] + v·cos(theta)·dt
y[k+1]     = y[k] + v·sin(theta)·dt
theta[k+1] = theta[k] + yaw_rate·dt
```

当前轨道中心线为 `track_y(x)=A·sin(2πx/λ)`；`A=0` 即直线。`--amp`、`--wavelength`、`--line-width` 分别设置轨道振幅、波长和黑线宽。该版本**没有**车体质量/横摆惯量、轮胎纵横向力、地面附着极限、侧滑、轮胎变形或碰撞。不要把精确运动学误解成精确车辆动力学。

### 3.3 灰度阵列

传感器位置先用车体姿态和前置距离投影到地面，再计算其相对轨道中心线距离 `d`：

```text
t = |d| / (line_width/2)
g = 1                         if t < 1
g = max(-1, 1 - 2·(t - 1))    otherwise
g' = clip(g·gain + offset + U(-noise, +noise), -1, 1)
```

这是用于控制验证的理想化反射响应：线内为 `+1`，背景逐渐趋向 `-1`。目前没有光源/反射率/环境光/传感器安装高度、光斑、ADC 量化或时间延迟模型。支持固定 seed 的均匀噪声、全阵列 gain/offset、随机 valid dropout 和硬件缺失 mask：

```text
--seed 23                 # xorshift 随机序列；0 使用固定默认 seed
--gray-noise 0.04         # U(-0.04, +0.04)，归一化灰度单位
--gray-gain 0.95          # 全通道增益
--gray-offset -0.02       # 全通道偏置
--gray-valid-prob 0.98    # 每次采样有效的概率
--gray-missing-mask 0x04  # bit 2 代表灰度数组第 2 路硬件缺失
```

`exist` 表示硬件安装状态，`valid` 表示本帧有效状态；sensor dropout 不会伪装成硬件不存在。所有输出仍保留原始仿真 value 和 mask，网络输入的置零/预处理仍由控制栈负责。

## 4. 日志、manifest 和 Godot 检视

- 核心 CSV 字段保持原顺序，末尾追加最多 16 组 `gray_value_NN, gray_exist_NN, gray_valid_NN`；旧 CSV 仍可回放。
- Manifest schema 现在为 `1.1.0`，记录 seed、scenario、车辆尺寸、传感器几何和电机/灰度模型参数。
- `nncar_replay` 仍按字段名读取控制量；schema validator 会验证可选灰度范围、mask 和缺失/有效语义。
- Godot 根据日志构建轨道/轨迹，并逐帧着色 Blender 车模的 8 路灰度传感器：有效读数用明暗表达，invalid 用橙色，硬件缺失变暗。它不产生或修改控制输出。

推荐运行：

```bash
bash simulator/run_demo.sh --amp 0.02 --wavelength 0.6 \
  --gray-noise 0.04 --gray-valid-prob 0.98 --gray-missing-mask 0x04 --seed 23
```

## 5. 后续提高模型保真度的顺序

1. **先做可辨识实验。** 用同一 2 ms 采样链记录电机 PWM/编码器阶跃，识别左右轮 `Kτ/I/b/deadband` 和母线影响；不要只靠调到“看起来像”。当前 `motor_identified.json` 是仿真台架产物，尚非实车真值。
2. **校准灰度传感器。** 测黑/白参考、线宽、安装高度和各通道增益/偏置；再决定是否加入光斑积分、量化、环境光和延迟。使用独立测试轨迹验证，避免只拟合训练样本。
3. **测量底盘侧滑。** 通过外部定位记录弯道横向/航向误差；只有实测显示无侧滑假设不足时，才加入车体质量、横摆惯量及轮地附着模型。
4. **必要时接 Webots/CoppeliaSim。** 用于碰撞、复杂接触或光学传感器研究。保持相同的 `step/observation`、profile 和日志契约，让 C 控制器仍是被测对象；不把 Godot 渲染物理当作新增真值。

每次模型升级应固定 seed、场景和 profile，保留旧基线并同时比较 CTest、CSV schema、闭环横向误差、失线率和传感器故障恢复。模型复杂度只有在改变决策/验收结论时才值得增加。

## 6. RL 环境预留接口

RL 使用独立的 reset/step 环境，不把 Godot 物理或渲染帧率当作训练真值。环境契约位于 `configs/rl_line_following.json`，C 进程为 `nncar_rl_env`，Python 适配位于 `tools/python/rl_env.py`。

- **动作**：二维连续值 `[-1,1]`，依次为归一化速度输出和归一化曲率输出。速度映射 `s_v=(a_0+1)/2`，曲率为 `kappa_norm=a_1`；之后调用 C 的 `nncar_twist_from_kappa`。
- **保留 C 栈**：RL 只替代 LineFollower 的 tracking policy 输出；现有 C 失线恢复状态机仍生效。速度/曲率包络、轮速混控、Safety、电机控制器、编码器量化及电机/底盘 plant 仍由现有 C 代码执行。
- **观测**：16 个灰度 value、16 个 hardware-exist mask、16 个 sample-valid mask，以及左右轮编码器估速。`x/y/theta`、横向误差和航向误差只放在 `info`/reward 中，不暴露给 policy，避免把仿真真值泄露进观测。
- **步进**：每次 policy action 保持一个 10 ms 控制周期；其中 C 栈/plant 按 profile 的 2 ms 电机步进运行 5 次。该节拍与当前 profile 的 100 Hz line loop 对齐。
- **episode**：默认 1000 步；超过 0.12 m 横向误差或 80°航向误差则 terminated，时间上限则 truncated。`reset(seed, options)` 可复现，并按配置随机化起始偏差、heading、轨道、灰度增益/偏置/噪声和缺失通道。
- **reward**：`1 − |e_lat|/e_limit − 0.25|e_heading|/heading_limit − 0.01(a_0²+a_1²)`；越界终止再减 1。reward 使用 plant 真值，训练 observation 不包含这些真值。
- **检查**：可选 Python logger 产出和现有 schema 兼容的 episode CSV/manifest；Godot 仅回放该 rollout，检查轨迹、传感器读数和动作输出，不参与环境步进。

当前接口方便后续接 PPO/SAC 等算法，但没有选择算法、训练策略或宣称泛化性能。先用固定 seed 的环境自测与 C 栈 baseline 建立对照，再逐步扩大 randomization 区间；实车参数仍需校准后才能讨论 sim-to-real。
