# 公共传感器与数据协议

本文件定义所有 Neural Module 共用的传感器缺失协议、归一化规则、数据格式和鲁棒性训练方法。

## 1. Value / Exist / Valid

```text
SensorField {
    value: float32
    exist: bool       # 硬件是否安装
    valid: bool       # 经过范围和 freshness 检查后的当前样本是否可用
    timestamp_us: uint64
}
```

数组传感器使用固定长度的 `value[]/exist[]/valid[]`，适合 MCU 静态内存。

约束：

1. `exist=0` 表示硬件没有安装，必须同时 `valid=0`。
2. `exist=1, valid=0` 表示硬件存在但本帧因超时、CRC、越界或异常不可用。
3. `valid` 是运行时 freshness/范围检查后的有效性；原始驱动状态应另存为诊断字段。
4. 进入网络前，必须先校准和归一化有效值，最后将 `valid=0` 的网络输入值置 0；禁止 NaN、Inf 或隐式 stale value。
5. 合法测量值为 0 时仍保持 `valid=1`，由 mask 区分合法零值和缺失值。
6. `exist` 来自硬件 profile，通常不逐帧变化；`valid` 可以逐帧变化。
7. 核心字段必须存在于消息结构。核心传感器失效时必须走确定性 fallback 或保护。

## 2. 通用消息

```text
GrayObservation     : value[16], exist[16], valid[16], timestamp, sequence
DesiredSpeed        : linear_mps, timestamp, command_ttl_us, source, health
TargetTwist         : linear_mps, angular_radps, timestamp, command_ttl_us, source, health
TargetWheelSpeed    : left_mps, right_mps, timestamp, command_ttl_us, source, health
DifferentialMixer   : TargetTwist + vehicle_profile -> TargetWheelSpeed
MotorObservation    : target_speed, actual_speed, optional fields, previous_applied_pwm
MotorCommand        : pwm_norm, timestamp, command_ttl_us, model_id, health
SafeActuatorCommand : bounded_pwm_norm, timestamp, command_ttl_us, stop_reason, health
```

所有消息带 `schema_version`、时间戳和序列号。`source` 用于区分 LineFollower、ManualControl、ObstacleAvoidance 等来源；不用于代替安全逻辑。

### 2.1 Command TTL

命令和传感器一样需要 freshness 检查。运行时计算：

```text
command_age_us = now_us - command.timestamp_us
command_fresh  = command_age_us <= command.command_ttl_us
```

建议初始 profile：

| 命令 | 初始 TTL |
|---|---:|
| DesiredSpeed | 100 ms |
| TargetTwist | 30 ms |
| TargetWheelSpeed | 30 ms |
| MotorCommand | 5 ms |

这些值必须通过实际调度和通信延迟验证。过期的 TargetTwist/TargetWheelSpeed 不得继续被无限保持；过期 MotorCommand 由 Safety Layer ramp down 或停车。

## 3. 归一化

所有归一化公式和参数写入 model bundle 的 `scaler`，训练和 MCU 推理不能使用两套隐含规则。

### 3.1 统一处理顺序

```text
Raw
  -> finite/range check
  -> calibration
  -> normalization
  -> apply effective valid mask
  -> network input
```

即：

```text
x_nn = normalize(calibrated_value)  if valid == 1
       0                            if valid == 0
```

`valid=0` 时置 0 的是最终网络输入值，不是原始传感器值。原始值、原始 valid、归一化前后的诊断信息仍可保存在 raw log 中。

### 3.2 灰度

```text
r = clip((raw - dark_reference) /
          (light_reference - dark_reference), 0, 1)
gray_value = 2*r - 1
```

黑线/白线极性写入数据 profile，不由输入协议猜测。

### 3.3 速度、PWM 和连续传感器

```text
speed_norm = clip(speed_mps / max_wheel_speed_mps, -1, 1)
pwm_norm   = clip(pwm_norm, -1, 1)
```

LineFollower 的 twist 使用 model profile 中共享的 `speed_ref_mps` 和 `omega_ref_radps`：

```text
desired_speed_norm = clip(desired_linear_speed_mps / speed_ref_mps, -1, 1)
omega_norm         = clip(angular_speed_radps / omega_ref_radps, -1, 1)
```

电压、电流、温度、加速度和负载使用 profile 固定的训练集 `mean/std`：z-score 后裁剪到 `[-5,5]`，再除以 5 得到 `[-1,1]`。

几何连续输入也必须归一化：

```text
position_norm       = clip(position_m / position_ref_m, -1, 1)
sensor_to_axle_norm = clip(sensor_to_axle_m / axle_ref_m, -1, 1)
```

`position_ref_m`、`axle_ref_m`、`speed_ref_mps` 和 `omega_ref_radps` 都属于 model profile，并随 scaler 一起部署。原始物理量仍保存在 calibration/raw log 中。

`exist/valid` 只取 0/1，不做 z-score。`dt_s` 使用秒；MLP 可忽略，Temporal Model 必须从接口接收。超出允许范围时设置 health fault，按策略 reset 或 fallback。

## 4. 数据文件

```text
data/
├── raw/<run_id>/*.jsonl|*.bin
├── datasets/line_v1/manifest.json
├── datasets/line_v1/episodes/*.npz
├── datasets/motor_v1/manifest.json
├── datasets/motor_v1/episodes/*.npz
└── calibration/<vehicle_id>/*.json
```

原始日志不可变；训练集是经过校准和对齐的派生物。`manifest.json` 至少记录 schema version、车辆和传感器 profile、单位、输入顺序、scaler、频率、数据生成版本和随机种子。

## 5. 坐标系和符号约定

公共协议固定使用：

```text
车体前方       +X
车体左侧       +Y
逆时针 yaw     +omega
左轮前进       +vL
右轮前进       +vR
sensor_position_m 左侧为正
logical positive PWM 表示车轮前进
```

差速 Mixer 使用 `track_width_m`：

```text
v_L = v - track_width_m/2 * omega
v_R = v + track_width_m/2 * omega
```

`track_width_m` 表示左右驱动轮接触点之间的距离；前后方向的轴距不是本 Mixer 参数。

## 6. Runtime Freshness 与速度估计

### 6.1 Sensor age 和 TTL

运行时根据：

```text
age_us = now_us - timestamp_us
valid_effective = source_valid
                  && finite
                  && range_ok
                  && age_us <= ttl_us
```

模型第一版不直接接收 age；`age_us` 用于 runtime 健康判断和日志。超过 TTL 后，runtime 将模型看到的 `valid` 置为 0，并记录 `stale_reason`。

初始 TTL 由 profile 配置，建议起点如下：

| 信号 | 典型频率 | 初始 TTL |
|---|---:|---:|
| gray | 100 Hz | 20 ms |
| actual speed | 500 Hz | 6 ms |
| motor current | 100 Hz | 30 ms |
| battery voltage | 5 Hz | 500 ms |
| temperature | 10 Hz | 1000 ms |

这些值需要用实际通信延迟和控制周期验证，不能硬编码进网络。

### 6.2 Encoder 与 VelocityEstimator

实际速度必须来自独立的估计器：

```text
Encoder
   ↓
VelocityEstimator
   ↓
actual_speed_mps + valid + timestamp
   ├──> PI/PID
   └──> MotorController NN
```

`VelocityEstimator` 可选择 count/window、pulse-period、互补估计和低通滤波等方法，但方法、窗口和滤波参数必须写入 profile。低速时不能简单使用 `delta_count / 2ms`；应使用自适应窗口或周期估计，并明确估计延迟。

PI、PID 和 NN 必须使用完全相同的速度估计输出，避免把输入滤波差异误判为控制器性能差异。

## 7. 时间对齐和数据切分

- 按完整 run、车辆、轨道/负载和电池条件切分 train/validation/test，禁止随机打散相邻帧。
- 由硬件时间戳对齐传感器、命令和编码器；延迟写入 `label_delay_s` 或 scenario metadata。
- 时序窗口跨 episode 时必须 reset，或使用明确 burn-in；隐藏状态不能跨 episode 泄漏。
- 无效标签、损坏时间戳和急停片段显式标记，不静默填补。

## 8. Sensor Dropout

Mask 不会自动产生鲁棒性，训练必须显式生成故障样本。

- **硬件缺失：** 对整个 episode/config 设置随机字段 `exist=0, valid=0`；校准和归一化后，最终模型 value 清零。
- **瞬时故障：** 对连续 burst 设置 `exist=1, valid=0`，模拟超时、CRC 错误和异常值；最终模型 value 清零。

灰度覆盖单路、多路和成片故障；电机覆盖 battery/current/temperature 等 optional 字段。核心 target 不 dropout。实际轮速失效不当作普通增强，必须同时测试 fallback。

Dropout 概率由低到目标值 curriculum 增加。不要将所有灰度屏蔽后继续作为普通回归样本；无信息时应标记为应急减速/停车样本。验证集分别报告 clean、hardware-missing 和 transient-invalid。

## 9. Domain Randomization

### 9.1 灰度

```text
g_i' = clip(a_i*g_i + b_i + epsilon_i, -1, 1)
a_i ~ U(a_min, a_max)
b_i ~ U(b_min, b_max)
epsilon_i ~ N(0, sigma^2)
```

还应覆盖反射率、每路增益/零点、整体环境光、局部强光、线路宽度、弯道、交叉线、丢线、横向扰动、速度变化、控制延迟和传感器延迟。

### 9.2 电机

覆盖电池电压、PWM 死区、编码器噪声/比例误差、负载、摩擦、电机常数、惯性、左右轮差异、PWM-to-torque 非线性、机械阻力、通信延迟、控制周期抖动和 optional 传感器缺失。

随机化不能替代完全未参与拟合的实车 test set。

## 10. 模型包和 MCU 约束

模型包必须包含：

```text
topology, weights, bias, activation
input_order, scaler, units
quantization, schema_version, model_version, checksum
```

部署使用固定数组、静态内存和固定输入维度。FP32 是参考版本；INT8/定点版本必须在离线 replay 比较输出误差、Flash、RAM 和 WCET 后才能上台架。
