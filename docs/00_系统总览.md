# 系统总体架构

## 1. 目标

建立可独立训练、验证、替换和部署的模块化神经控制系统，而不是一个从所有传感器直接输出 PWM 的端到端网络。

```text
Perception / Task Module
          ↓
      Target State
          ↓
Low-level Control Module
          ↓
   Safety / Actuator
```

第一阶段采用差速双轮模型，左右轮速度单位为 `m/s`，PWM 在模块内部统一使用 `[-1, 1]`。

## 2. 第一阶段架构

```text
GrayObservation + DesiredSpeed
              ──> LineFollower ──> TargetTwist(v, omega)
                                         │
                               DifferentialDriveMixer
                                         │
                                   TargetWheelSpeed
                                         │
Encoder/optional motor sensors ─────────┘
                                         ▼
                          MotorController L/R
                                         ▼
                               Safety / Limit
                                         ▼
                               Actuator Adapter ──> PWM
```

### 模块职责

| 模块 | 读取 | 不读取 | 输出 |
|---|---|---|---|
| LineFollower | 灰度值、存在/有效标记、期望基础速度、时间 | PWM、编码器、电机参数、相机、蓝牙 | `v, omega` |
| DifferentialDriveMixer | `v, omega`、底盘轮距 | 灰度、PWM、电机状态 | 左右轮目标速度 |
| MotorController | 目标轮速、实际轮速、上一 PWM、电机侧可选观测 | 灰度、相机、导航原因、遥控原因 | 单轮 PWM |
| Safety Layer | 网络输出、实际轮速、传感器健康、供电、电流、温度、通信状态 | 不依赖 NN 推断安全行为 | 限幅命令或急停 |
| Actuator Adapter | 安全命令和硬件 PWM 配置 | 上层传感器 | 方向和 duty |

模块之间使用带版本的消息通信，禁止直接访问其他模块的内部状态。

## 3. 公共模块 API

```text
reset(reason)
step(input, dt_s) -> output
get_state() -> state/diagnostics
load_model(model_bundle) -> status
```

无状态 MLP 的 state 为空；GRU、LSTM 和 CfC/LNN 的 state 只包含 hidden state、时间戳和健康信息。

## 4. 未来模块扩展

未来的 ManualControl、ObstacleAvoidance、CameraFollower、PathPlanner 等模块统一产生或竞争 `TargetTwist`：

```text
LineFollower ──────────┐
ManualControl ─────────┤
ObstacleAvoidance ────┼──> Command Selector -> TargetTwist
CameraFollower ───────┤                              ↓
PathPlanner ───────────┘                    DifferentialDriveMixer
```

底盘 Mixer 统一使用：

```text
v_L = v - L/2 * omega
v_R = v + L/2 * omega
```

底层电机模块不因上层策略增加而改变；`track_width_m` 属于 Mixer/vehicle profile，不进入 LineFollower。

## 5. 运行频率

| 任务 | 默认频率 | 责任 |
|---|---:|---|
| Gray acquisition | 100 Hz | 采样、校准、有效性检查 |
| LineFollower | 100 Hz | 产生 `v, omega` |
| Encoder acquisition | 500 Hz | 更新实际轮速 |
| MotorController L/R | 500 Hz | 闭环输出 PWM |
| Safety Layer | 不低于 500 Hz | 每次执行器更新前检查 |
| Logger/diagnostics | 50–100 Hz | 不阻塞控制任务 |

MotorController 在两个 LineFollower 周期之间保持最新目标，并记录 target age。目标超过自身 `command_ttl_us` 时进入安全退化；MotorCommand 超时也必须由 Safety Layer 检查。

每个任务都必须测量 worst-case execution time、调度抖动、输入 age、推理延迟和 Safety Layer 延迟。控制路径不得动态分配内存或等待磁盘/网络。

## 6. 独立安全层

安全层固定位于网络输出之后：

```text
Neural Controller
  -> health check
  -> clamp
  -> rate limit
  -> deterministic fault policy
  -> Actuator Adapter
```

必须由普通逻辑实现：

- command limits：最大 PWM、PWM slew rate、目标速度和目标加速度；
- physical-state limits：实际轮速超速、过流、过温、堵转和电池欠压；
- 通信超时、模块 watchdog、核心编码器失效、NaN/Inf 和 Emergency Stop。

Safety Layer 必须读取 `VelocityEstimator` 输出的实际左右轮速度；仅限制 PWM 不能保证下坡或外力驱动时不超速。

默认策略是：短时命令 stale 时 ramp down；核心反馈或通信持续失效时停车；急停立即禁止驱动。NN 无权修改安全阈值。

## 7. MCU 部署约束

- 先完成 Python/CPU replay，再适配 CMSIS-NN、TFLite Micro 或厂商推理库。
- 模型包包含拓扑、权重、bias、激活、输入顺序、scaler、单位、量化参数、版本和 checksum。
- MCU 只使用固定数组和静态内存，不使用动态 shape。
- LineFollower 目标少于 10k 参数；单个 MotorController 目标少于 2k 参数。
- 同时保留 FP32 参考和 INT8/定点候选，量化后先离线回放再上台架。
- 推理错误只产生 health fault，由 Safety Layer 处理。

## 8. 系统联调原则

```text
每个模块独立训练
        ↓
每个模块独立验证
        ↓
冻结模块
        ↓
消息和调度联调
        ↓
实车验证
```

第一阶段不进行 `Gray → LineNN → MotorNN → PWM` 的联合训练。等模块化闭环稳定后，再单独研究 joint fine-tuning。

## 9. 坐标系和符号约定

全系统统一使用：

```text
车体前方       +X
车体左侧       +Y
逆时针 yaw     +omega
左轮前进       +vL
右轮前进       +vR
sensor_position_m 左侧为正
logical positive PWM 表示车轮前进
```

Actuator Adapter 负责将 logical positive PWM 映射到实际电机接线极性；电机线序不能污染上层数学符号。

Mixer 使用：

```text
v_L = v - track_width_m/2 * omega
v_R = v + track_width_m/2 * omega
```

这里的 `track_width_m` 是左右驱动轮接触点之间的距离；前后方向的轴距不参与该 Mixer 公式。

## 10. MVP 顺序

### MVP-0：冻结契约

固定消息 schema、单位、最多 16 路的物理位置排序、输入顺序和 model manifest；建立 schema validator 与 CPU replay 规范。

### MVP-1：传统闭环

先完成灰度 PID/丢线状态机、左右轮 mixer、左右 PI/PID、Safety Layer 和日志。没有 NN 时也必须能够安全运行和回放。

### MVP-2：LineFollower MLP

训练并验证包含 `desired_speed` 的 LineFollower MLP，输出 `v, omega`，由 Mixer 转为左右轮目标速度；与灰度 PID 做离线和受控实车对比，冻结后再进入系统联调。

### MVP-3：左右 MotorController MLP

训练两个 6 维核心/电池输入 MLP，比较 Pure NN 与 Residual PI+NN；NN 故障时 residual 必须为 0。

### MVP-4：冻结模块并联调

```text
Gray + desired_speed -> LineFollower -> TargetTwist(v, omega)
                     -> Mixer -> TargetWheelSpeed
                     -> MotorController(L/R) -> Safety -> PWM
```

联调阶段只处理消息对齐、调度周期、限幅和故障策略，不做端到端反向传播。

### MVP-5：鲁棒性和导出

加入 sensor dropout、噪声和 domain randomization，建立 clean/fault/未见车辆测试矩阵；先导出 FP32，再验证 INT8/定点的误差、内存和延迟。
