## 0. 结论

- 分层架构成立，保留：`LineFollower -> Mixer -> MotorController -> Safety -> Actuator`。
- 第一阶段不做端到端训练，不做 `Gray -> NN -> MotorNN -> PWM` 联合训练。
- 项目最大的风险已从“架构错误”转为“实验设计”：**LineFollower 的 teacher 质量、数据覆盖、仿真保真度**。
- 如果 LineFollower NN 在固定车、固定阵列上都不能证明相对 PID 的闭环增量，就不扩大到跨车辆。
- 平台冻结为 **STM32 + C11**；MVP 先 FP32，INT8/CMSIS-NN 后置。

## 1. 冻结决策摘要

| 项目 | R3 决策 | 理由 |
|---|---|---|
| LineFollower 输入 | 68 维，增加 `line_confidence`、`valid_count_norm` | 让网络感知退化程度，交接阈值与输入使用同一套定义 |
| LineFollower 输出 | `[s_v, kappa_norm]`，确定性换算 `v = s_v * v_desired`、`omega = kappa * v` | 速度与轨迹几何解耦，跨速度泛化更合理 |
| 角速度包络 | `omega` 必须过运动学上限和横向加速度上限 | 防止单轮超速和不可达曲率 |
| Mixer | 等比例降饱和，输出 `lambda`、`kappa_target`、`kappa_achieved` | 单轮独立限幅会改变曲率 |
| 丢线 | 确定性 Recovery State Machine 接管，NN 不负责搜索 | 无状态 MLP 没有“线最后在哪边”的记忆 |
| Motor 输入 | 7 维 residual：核心 4 维 + `V_rail` + 电压有效位 | residual 必须看见 PI 基线 `u_pi` |
| Motor 结构 | 默认 `PI + residual NN`，NN 故障时 `delta=0` | 安全退化路径最短 |
| 安全层 | 非 NN、确定性、最坏情况阈值 | NN 无权修改安全阈值 |
| 时序 | LineFollower 100 Hz；Motor/Safety 500 Hz | 内环/外环保留 5:1 |
| 电源 | 4S 电池 + 12V 稳压给电机，按 `V_rail = 10.5~12.3V` 建模 | 稳压器有压降、限流和低压 dropout |
| 泛化 | `family` 训练分布 + `instance` 部署描述 + `unobserved` 随机化 | 纯随机化不能替代架构和描述符 |
| 数据 | 原始日志不可变；schema + replay + golden log 先于 NN | 没有可回放数据，训练和验收都不可信 |
| 仿真 | 电机 plant + 运动学/灰度 plant 必须在 MVP-1 建立 | 否则跨车辆、故障注入、DAgger 都只能靠实车 |

## 2. 平台与预算

### 2.1 选型

- 推荐 **STM32G431/G474**（170 MHz，Cortex-M4F，HRTIM、比较器、运放、USB）或 **STM32F405**。
- 裸机定时器调度优先；只有 USB/CAN 协议栈需要时才引入 FreeRTOS。
- 目标：控制路径无动态分配、无阻塞、无文件系统访问。

### 2.2 算力与内存

| 项目 | 数值 | 说明 |
|---|---:|---|
| LineFollower 参数 | 7,058 | 68 -> 64 -> 32 -> 16 -> 2 |
| Motor 参数 | 929 / 轮（7 维 residual） | 31 维完整版本为 1,697 |
| 计算量 | LF 7.1k MAC @100 Hz；Motor 0.93k x2 @500 Hz | 合计约 1.6 MMAC/s |
| 推理时间 | LF 最坏约 0.2 ms；Motor 约 30 us | M4F 170 MHz，FP32 估算 |
| CPU 占用 | Motor 双轮约 3%；LF 约 2% | 余量充足 |
| Flash | FP32 约 35 KiB；A/B 双槽约 70 KiB | 256 KiB 的 G4/F4 足够 |
| RAM | 激活 < 1 KiB；日志 ring 16–32 KiB | 128 KiB 足够 |
| INT8 | 权重约 9 KiB；A/B 约 18 KiB | 后期再做，不作为 MVP 目标 |

### 2.3 工具链与实现约束

- `arm-none-eabi-gcc -O2 -ffp-contract=off -fno-fast-math`，禁用异常和 RTTI。
- MVP 使用自研 FP32 全连接运行时（§2.4）；7k 参数用 TFLite Micro 是负优化。
- INT8 阶段再用 CMSIS-NN；输入层使用对称量化、`zero_point=0`，避免 mask 置 0 变成非零量化值。
- 末层 `sigmoid/tanh` 保留 FP32 或查表；量化误差必须用 golden vector 对拍。
- 模型包 A/B 双槽、CRC32、原子切换、回滚；维度或校验失败时只跑 PI。
- 用 DWT 记录 worst-case execution time；IWDG 覆盖控制任务。

### 2.4 推理运行时（`nncar_nn`）

`firmware/core/include/nncar/nn.h` + `firmware/core/src/nn.c`，x86 编译后 873 B 代码。两个模型共用同一份内层循环，原先 line.c / motor.c 各有一套重复实现。

```c
typedef struct { uint16_t in, out; uint8_t act; const float *w; const float *b; } nncar_nn_layer_t;
typedef struct { const nncar_nn_layer_t *layers; uint8_t count; } nncar_nn_model_t;

uint16_t nncar_nn_scratch_len(const nncar_nn_model_t *m);   /* 2 × 最宽层 */
void nncar_nn_forward(const nncar_nn_model_t *m, const float *x, float *y, float *scratch);
```

五条刻意的取舍：

1. **只有全连接，没有通用 tensor**。模型本身就是 MLP，shape/stride/broadcast 只会增加出错面。
2. **权重按指针寻址，不拷贝不重排**。同一份运行时既吃生成的结构体（`nncar_line_nn_t`），也吃未来可能出现的 flash blob 或测试夹具；零数据搬运。
3. **形状检查留在编译期**。结构体仍是定长的 `float w1[64][68]`，生成器仍校验维度/激活/`trained`，所以运行时没有分支判断。
4. **无 malloc**。scratch 由调用方提供，`nncar_nn_scratch_len()` 给出需求；line 是 128 float。
5. **末层恒为 `ACT_NONE`**。line 的头是 `sigmoid(s_v)` 与 `tanh(κ)` 两种激活并存，一域一激活表达不了，于是头部语义留在模型侧（`nncar_line_nn_eval` 对 logits 做两次激活）；motor 的单输出 `tanh` 同理。

代价与边界：

- 栈：line 推理从 448 B 升到约 590 B（4 个层描述符 + 128 float scratch），仍在 §2.2 的 1 KiB 预算内。
- 精度：`test_nn` 用改造前抓的 golden 锁定累加顺序（line `0.891498804 / 0.710869074`，motor `0.0230435599 / 0.999193072`，容差 1e-9）；闭环 `--check` 与 `baseline --check` 数值逐位不变。
- 去 libm：只剩 `expf/tanhf` 两个调用，需要时替换 `layer_act` 里的实现并重跑 golden 即可。
- 不是自动微分框架，也不承担训练；训练仍在 host 用 numpy 手写反传（§4.4/§6.3）。

| 标称 | 14.8V |

### 3.3 12V 稳压与 `V_rail`

稳压器不是“恒定 12V”，而是**有界、可测、随负载和电量变化**：

- buck 只能降压，4S 放到 12.0V 附近进入 dropout；
- 负载调整率 0.1–0.5V；
- 电流限折返可能跌到 9–10V；
- 线缆和接插件 0.1–0.5V；
- 纹波/瞬态 100–300mV；
- 设定值公差 ±1–2%。

因此在**电机驱动端**采样的 `V_rail` 典型为 **10.5–12.3V**。

规格建议：

- 12V 10A 连续、15A 峰值，带 OCP/OVP/OTP、软启动、输出电容和 EMI 布局。
- `V_rail` 在驱动端采样，500 Hz，10 ms TTL；不要用稳压器输出端代替。
- 驱动耐压按 >= 20V 选；**TB6612 绝对最大 15V，禁止用于 4S**。推荐 DRV8874 / DRV8871 / BTS7960。
- 双电机堵转 10A 是稳压器下限；否则把电机限流设到 2.5–3A/轮。
- 失效直通是真实风险：buck 加 OVP，驱动加 TVS，电池加保险丝。

有效最高速：

```text
v_max_eff = v_max_nom * clip(V_rail / 12.0, 0.75, 1.05)
```

外环 `v_desired`、Safety 上限和前馈都应使用 `v_max_eff`，不能只用 `v_max_nom`。

## 4. LineFollower R3

### 4.1 输入输出

```text
x_line[68] = [
  gray_value[16], gray_exist[16], gray_valid[16], position_norm[16],
  sensor_to_axle_norm, desired_speed_norm,
  line_confidence, valid_count_norm
]

y_line = [s_v, kappa_norm]
s_v        = sigmoid(...)  in [0, 1]
kappa_norm = tanh(...)     in [-1, 1]
```

计算：

```text
v_target    = s_v * v_desired
kappa_target = kappa_norm * kappa_ref
omega_target = kappa_target * v_target

omega_kin = 2 * (v_max_eff - v_target) / L
omega_lat = a_lat_max / max(v_target, 0.05)
omega_target = clamp(omega_target, -min(omega_kin, omega_lat), +min(...))
```

- `kappa_ref` 由车辆几何定，初期 5–8 1/m，写入 profile。
- `a_lat_max` 初期 3.5 m/s²，标定后调整。
- `v_target = 0` 时 `omega = 0`；文档明确“不支持原地转向”。
- 68 维版本参数量 **7,058**（仍小于 10k）。

### 4.2 标签注意事项

- `kappa = omega / v` 在低速会放大噪声；只在 `v >= v_min` 且置信度足够时计算，或按 v 加权。
- 如果 teacher 是 PID，NN 的上界就是 PID；MVP-2 必须先明确增益假设和验收门槛。

### 4.3 置信度与丢线交接

```text
q_i   = valid_i * (g_i + 1) / 2      # 线 = +1，背景 = -1
conf  = clip(sum(q_i) / 2.0, 0, 1)
enter recovery : conf < 0.25 持续 30 ms
exit recovery  : conf > 0.60 持续 50 ms
NN 生效        : conf >= 0.35 且 valid_count >= 2
```

Recovery State Machine：

- 输入：`last_valid_centroid`、`last_omega`、`time_since_valid`、`v_actual`。
- 行为：按最后有效方向搜索；`v_search = 0.3 m/s`；`|kappa_search| = 0.4 * kappa_ref`。
- 500 ms 未重捕获则停车；重新捕获后用 200 ms ramp 交还 NN。
- 每次切换记录 reason。
- MVP 不给 MLP 塞 `last_error` 等历史特征；历史由状态机或后续 GRU/CfC 负责。

### 4.4 闭环 A/B：MLP vs PID（实测结论）

目的：回答“68 维单帧 MLP 是否能在同一闭环里超过灰度 PID”。实验工具 `firmware/host/src/line_ab_main.c`（`nncar_line_ab`），同一 plant、同一 stack、同一 8 个场景，只换 LineFollower。

场景（8 个，各 6 s，指标跳过前 0.5 s）：

```text
straight     直线，1 cm 横向偏置、3° 初始航向
gentle_s     A=0.08 m, λ=1.6 m, v=0.9
sharp_s      A=0.12 m, λ=0.9 m, v=0.6（κ≈5.85 1/m，接近 kappa_ref=6）
fast_gentle  A=0.06 m, λ=1.6 m, v=1.2
noise        同上加白噪声 0.08、通道增益 ±12%、零偏 0.05
dropout      gentle_s + 两路传感器 exist=0 + 10% 时刻 valid=0
rail_sag     A=0.10 m, λ=1.2 m, v=0.75, 母线 11.0 V
disturbance  直线，3 cm 偏置、5° 初始航向、v=1.2
```

指标：GT 横向误差 RMS（`y - track_y(x)`）、最大横向误差、出线时间占比、相邻 line tick 的 yaw 抖动 RMS（Δω）、平均线速度。

教师（只在 `--dump-teacher` 里出现，不进固件）：Stanley 型 GT 路径跟踪

```text
kappa = kappa_path - ke*e_lat + ktheta*(theta_path - theta)
ke = 80 1/m^2, ktheta = 10 1/m, 与 PID 同量级的激进程度
v     = min(v_desired, sqrt(0.85*a_lat_max/|kappa|))，并套用同一运动学包络
```

它比 PID 好 3.5 倍（聚合 0.0020 vs 0.0070），说明“有真实增量空间”，不是天花板为零。

数据（`nncar_line_ab --dump-teacher`，二进制 float32，行 = 68 输入 + 2 标签）：

- 120 episode × 6 s × 100 Hz；轨道/初始位姿/速度/母线随机化，噪声/增益/丢传感器按 1/4–1/7 概率注入。
- 每个 episode 跑三条闭环：GT oracle、PID、**当前学生**；三条的状态都用 oracle 重新标注。学生的那些行提供 DAgger 式覆盖，否则训练分布只覆盖 PID 的轨迹。
- 合计 216,000 行；`tools/python/train_line_nn.py` 做 episode 级 80/20 划分、Adam、60 epoch、按 val 取最优。

结果（可复现配方，见下）：

| 场景 | PID | MLP | GT oracle |
|---|---|---|---|
| straight | 0.0024 | 0.0025 | 0.0013 |
| gentle_s | 0.0048 | **0.0019** | 0.0014 |
| sharp_s | **0.0102** | 0.0159 | 0.0037 |
| fast_gentle | 0.0052 | **0.0020** | 0.0016 |
| noise | 0.0052 | **0.0024** | 0.0014 |
| dropout | 0.0119 | **0.0052** | 0.0014 |
| rail_sag | 0.0076 | **0.0051** | 0.0024 |
| disturbance | 0.0029 | **0.0025** | 0.0016 |
| **聚合** | **0.00703** | 0.00643（+8.6%） | 0.00200 |

- 教师拟合：val MSE 0.0052，R²(κ)=0.856；标签 κ_norm 标准差 0.239。
- yaw 抖动（Δω RMS 的 8 场均值）：PID 1.12 rad/s，MLP 0.114 rad/s，**约平滑 10 倍**。PID 在 `dropout` 场景有 6.3 rad/s 的抖振，MLP 为 0.55。
- 出线时间占比：两者都是 0。

验收门槛（结果前声明）：聚合 RMS 至少低 10%，且任一场景不得比 PID 差 10% 以上。结论 **FAIL**：

```text
FAIL: aggregate MLP rms is not 10% below PID        (+8.6%)
FAIL: sharp_s MLP 0.0159 is >10% worse than PID 0.0102   (+56%)
```

失败机理（当时的判断，结论已被 §4.6 修正）：

- 68 维输入是**单帧**观测，8 路灰度在同一纵向站位，因此一个快照只能给出“线在哪里”，给不出“线的走向/曲率”，也拿不到 PID 的 D 项所依赖的历史。
- 用开环探针（直线 + 横向偏置）测已训练网络：增益约 120 1/m²，与 PID 的 kp=80 同量级；但输出被**条件均值压缩**：|偏置|=20 mm 时 κ_norm 只有 0.42（κ≈2.5 1/m），而 `sharp_s` 需要 κ_norm≈0.97。左弯与右弯在同一观测下不可区分，标签互相抵消，均值必然偏小。
- 中央还有 2 mm 的死区和一个 −0.018 的常值 κ 偏置（ω≈−0.1 rad/s），来自同一抵消效应。
- 结果：在温和轨道上 MLP 明显更好（1.9–2.5 倍），一旦需要的曲率达到观测无法分辨的量级，MLP 就会“打不够舵”。PID 靠 D 项和降速硬扛过去。

决策（初判）：**固件默认仍用 PID**，“同一个 MLP 换掉 PID”不成立。下一步方向见 §4.5。本工具与训练链路保留，作为后续形式的对照基线。

**后续（§4.6）**：这个 FAIL 的主因不是信息不足，而是 MSE 训练导致的幅值压缩。加一个标量闭环增益后同一个网络就能通过门槛，缺省值改由 profile 的 `line.kappa_gain` 承载。

可复现配方（确定性，两步）：

```text
# 1) 先把 configs/line_nn_weights.json 置零（全零网络），重编译
cmake --build build
./build/nncar_line_ab --dump-teacher build/line_teacher_a.bin --episodes 120 --seed 1
python3 tools/python/train_line_nn.py --data build/line_teacher_a.bin --epochs 60
cmake --build build
# 2) 用训练出的学生再采一次（学生入环），再训练
./build/nncar_line_ab --dump-teacher build/line_teacher.bin --episodes 120 --seed 1
python3 tools/python/train_line_nn.py --epochs 60
cmake --build build
./build/nncar_line_ab --check
```

注：`nncar_line_ab --check` 是里程碑验收，**不挂进 ctest**；ctest 只跑 `nncar_line_ab` 冒烟，保证闭环与网络路径不坏。加入 `line.kappa_gain` 后该检查已**判 PASS**（见 §4.6），但仍不进 ctest，因为它是标定工具而不是回归基线。

### 4.5 历史特征消融（70 维）与可观性分析

检验 §4.4 的“缺时间信息”假设。做法：把 PID 的 ė 用**同一个** 20 Hz 一阶滤波器做成 2 个确定性特征补回网络（68 → 70 维，7,058 → 7,186 参数），PID 与 MLP 共用同一份 `d_filtered`（`nncar_line_history_update()`），其余配方与 A/B 完全不变。

| | 68 维 | 70 维 |
|---|---|---|
| 聚合 RMS | **0.0064** | 0.0287 |
| sharp_s | **0.0159** | 0.0795（出线 56.7%） |
| 训练 R²(κ) | 0.856 | 0.847 |

同一配方可逐位复现（68 维两次都是 MSE 0.00521 / 聚合 0.0064），所以这不是训练噪声：**这 2 个特征没有带来增益，反而更差**。已回退到冻结的 68 维。

为什么没用 —— 可观性分析（`tools/python/line_observability.py`，在教师数据上做 ridge 回归，按 episode 划分）：

| 特征 | R²(κ_norm) |
|---|---|
| 68 维单帧（线性） | 0.661 |
| 当前质心 | 0.587 |
| 当前质心 + 上一帧 + 滤波 ė | 0.610 |
| 最近 10 帧质心（0.1 s） | 0.611 |

## 5. Differential Mixer R3

```text
vL = v_target - L/2 * omega_target
vR = v_target + L/2 * omega_target

lambda = min(1, v_max_eff / max(|vL|, |vR|))
vL_star = lambda * vL
vR_star = lambda * vR

kappa_achieved = (vR_actual - vL_actual) / (L * max(v_actual, 0.05))
```

- 等比例缩放保持瞬时曲率 `(vR - vL) / (vR + vL)`。
- 但几何缩放不保证内环可跟踪；Mixer 必须输出 `lambda`、`kappa_target`、`kappa_achieved`。
- 外环在 `lambda < 1` 持续 20 ms 或轮速跟踪误差超阈值时，按 10%/100 ms 降 `v_desired`，最低 0.2 m/s，并记录 `curvature_tracking_fault`。
- Safety 保留硬限幅作为故障路径，不参与正常曲率整形。

## 6. MotorController R3

### 6.1 输入与参数

```text
x_motor[7] = [
  target_speed_norm, actual_speed_norm, previous_applied_pwm_norm,
  u_pi_norm, V_rail_norm, V_rail_exist, V_rail_valid
]
```

- residual 必须看见 `u_pi`；否则无法准确学习 `expert - u_pi`。
- 7 维参数 **929**；完整 31 维参数 **1,697**。
- `V_rail` 取代原来的 battery 输入；电池电压降为诊断和安全信号。

### 6.2 控制律

```text
u_pi  = clamp(Kff * v_target / v_max_eff + Kp*e + Ki*I, -1, 1)
u_nn  = alpha * tanh(NN(x_motor))
u_cmd = clamp(u_pi + u_nn, -1, 1)
```

- `alpha` 初期 0.25，模型加载时 ramp。
- PI anti-windup 使用 back-calculation，反馈量必须是安全后的实际 PWM，`Tt = 50 ms`；急停/故障时冻结并清零积分。
- 死区先做确定性前馈补偿，residual NN 学剩余。
- NN 输出 NaN/Inf 或推理超时：`u_nn = 0`，PI 接管；连续 3 周期锁存 NN fault。
- `actual_speed` 无效：bypass NN 和 PI，进入 ramp-down/stop，不伪装成正常闭环。

### 6.3 基线与教师

必须分四档比较：

1. `plain PI`；
2. `PI + 确定性前馈/死区/电压补偿`；
3. `PI + residual NN`；
4. `NN direct`（网络直接出指令，无 PI、无积分）。

第 4 档不是候选方案，是用来回答“网络能不能**替掉**环路而不是修补它”的对照。
教师不能是 PI，否则 residual 标签恒为 0。使用辨识模型上的 MPC、逐工况优化或迭代学习（已落地为 H 步 MPC 残差教师，见下）。

实现状态：

- 四档已统一到 `nncar_motor_step()`，由 `nncar_motor_mode_t` 选择；`nncar_stack_set_motor_mode()` 负责切换。
- `PI` 只走 `Kp*e + Ki*∫e`，不做前馈、不做死区补偿。
- `PI_FF` 增加 `Kff*v_target/v_max_eff` 前馈、母线缩放与确定性死区补偿。
- `PI_RESIDUAL` 在 `PI_FF` 之上叠加 `alpha*tanh(MLP(x))`；网络为零或指针为空时逐位退化为 `PI_FF`，是安全降级路径。
- `NN_DIRECT` 令 `u_cmd = tanh(MLP(x))`，输入 `x[3]` 恒置 0（看不到 PI 状态），积分器冻结；网络为空时退化为 `PI_FF`。
- 对比工具 `firmware/host/src/baseline_main.c`（ctest `baseline_modes`）在同一 plant、同一两段速度阶跃（0 -> 0.8 -> 0.4 m/s）下输出 rms 误差、超调、上升时间、调节时间、稳态误差、饱和占比与能耗；另跑一组母线下陷 12.0 -> 10.8 V。

| 12.0 V | PI | 0.1089 | 0.0% | 1.178 s | 0.0104 |
| 12.0 V | PI+FF | 0.0545 | 1.6% | 0.458 s | 0.0017 |
| 12.0 V | PI+residual | 0.0478 | 0.0% | **0.042 s** | 0.0013 |

教师定义（`tools/python/motor_teacher.py`）：

- **候选 A 被实测淘汰**：一步精确模型逆（`drive* = v_ss / (g * rail_ratio)`）。标签是 `(u_star - u_pi) / alpha`，要求学生复现一个绝对指令，等价于抵消 PI 反馈；作为 oracle（给真实 plant 参数）在 held-out 上比 PI+FF 差 12.7%，在 nominal 两段阶跃上差 37.9%。纯静态前馈在目标快速变化时没有反馈，越学越差。
- **采用方案 B：有界残差上的 H 步 MPC**。每个访问到的状态选 `delta ∈ [-1, 1]` 最小化 `Σ_{j=1..H} (v[k+j] - target)^2`；只把 `u_cmd = clamp(u_pi + alpha*delta)` 施加一步，之后仍由 PI+FF 接管；目标与母线在视界内零阶保持（不做预言）；plant 取辨识值。`H = 10`（20 ms）、17 档候选、标签范围 ±0.96（避开 tanh 平尾）。候选打平时选 `|delta|` 最小者，否则饱和状态下会错误地输出满幅负残差。
- 教师 oracle 上界（真实 plant、`alpha = 0.25`、`H = 10`）：held-out 0.17926（+20.9%）、nominal 0.04762（+12.6%）。
- 标签即 `t = delta`，学生输出 tanh 参数，`u_nn = alpha*t`；零网络仍逐位退化为 `PI+FF`。

### 6.5 台架辨识

激励、采集、辨识、真值比对构成一条可回归的链路：

```text
firmware/host/src/bench_main.c       四阶段激励 + CSV + 可选 truth JSON
tools/schema/bench_log.schema.json   台架日志契约
tools/python/identify_motor.py       CSV -> 每轮 deadband / static_gain / tau
configs/motor_identified.json        辨识产物（当前为仿真台架，verified=false）
```

激励顺序：

```text
phase 1  正向死区阶梯     +0.01 .. +0.12，步长 0.01，每段 0.25 s
phase 2  正向速度阶跃     +0.20 / +0.35 / +0.50 / +0.70 / +0.90，每段 0.40 s
phase 3  静止 0.5 s -> 反向死区阶梯 -> 反向阶跃 -0.35 / -0.70
phase 4  母线灵敏度       pwm 固定 +0.50，V_rail 11.0 / 10.5 / 12.0 V
```

- **不做死区补偿**：日志必须记录原始 PWM，否则死区不可观测。
- 反向扫描前必须有静止段，否则正向扫速的惰行会被误判为越过反向死区。
- 每段用 `y[k] = A + B * lambda^k` 拟合（一阶对象在恒定 `dt` 下精确）；`A` 是稳态速度，`tau_hat = -dt / ln(lambda)`。
- 死区与增益由 `|v_ss| = a*|pwm| + b` 的斜率与截距给出：`deadband = -b/a`、`static_gain = a+b`，不需要任何死区先验；死区阶梯再给出 0.01 量化的交叉校验。
- `tau` 只取激励充分（`u_eff >= 0.25`）的段；近死区段受静摩擦支配，不进入线性模型。
- 母线段验证 `v_ss ∝ V_rail`：忽略母线时误差 8%–12.5%，按 `V_rail/12` 归一后 < 0.01%。
- `tau_hat` 是采样系统的等效时间常数，`tau_hat ≈ J/B - dt/2`（`dt = 2 ms` 时约 −2%），不能当成连续时间常数直接反推 `J`。
- 验收门槛（ctest `bench_identify`）：`static_gain` 相对误差 < 3%，`tau` < 10%，`deadband` 绝对误差 < 0.01。
- 仿真台架注入的可辨识真值（右轮 `gain_scale = 0.93`、`damping_scale = 1.08`）已被完整恢复，见 `configs/motor_identified.json`。
- 实车替换：台架固件输出同一 CSV，运行 `identify_motor.py --out configs/motor_identified.json`；确认后再并入 `configs/vehicle_default.json` 并把 `verified` 置为 true。

### 7.2 硬件路径

- 过流和急停必须走硬件：驱动 nFAULT、比较器、断使能，不依赖 500 Hz 软件检查。
- 电机与逻辑分开供电；BOR、母线电容、预充和 TVS 必须评估。
- 停车默认 coast；主动刹车策略需单独验证，避免高速翻转。

## 9. 数据、DR 与模型包

### 9.1 数据

- 原始日志不可变；训练集是校准、对齐后的派生物。
- `manifest` 至少包含：schema version、vehicle profile、输入顺序、scaler、频率、数据生成版本、随机种子、git commit。
- 按完整 run / 车辆 / 轨道 / 电池条件切分；禁止随机打散相邻帧。
- 时序窗口跨 episode 必须 reset 或使用明确 burn-in。
- 无效标签、损坏时间戳、急停片段显式标记。
- Golden log：每个模式 10 s；FP32 相对误差 < 1e-4；INT8 输出绝对误差 < 0.02。
- Replay 支持离线加速和实时两种模式；可注入 stale、NaN、dropout、饱和、模型维度不符。

### 9.2 随机化的四层

| 层 | 内容 | 用途 | 是否随机 |
|---|---|---|---|
| Family | 减速比、轮径、L、N、轴距、v_max 范围 | 训练分布 / 仿真生成 | 是 |
| Instance | 这一辆车的真实几何、`v_max`、`V_rail`、电流限 | 部署描述、scaler、安全限幅 | 否 |
| Unobserved | 摩擦、R(T)、ESR、增益漂移、环境光、负载、死区波动 | 让策略在不确定下稳定 | 是 |
| Safety | v_max、电流/温度/欠压阈值、TTL | 保护硬件 | 绝不随机 |

核心原则：**随机化是对未观测参数的边际化**。已经作为网络输入的参数不需要重随机；安全阈值和结构常数不能随机。

### 9.3 泛化三轴

| 轴 | 机制 | 实现 |
|---|---|---|
| 传感器几何 | 架构 | shared sensor encoder + mask + position；扁平 MLP 做不到 |
| 车辆动力学 | 归一化 + 描述符 | 用 `v_max` 归一化速度，吸收减速比/轮径；必要时加 plant descriptor |
| 环境与故障 | DR + 标定 | 光照、增益、dropout、负载、延迟 |

`L`、减速比、轮径**不进入 LineFollower**，属于 Mixer/vehicle profile；因此 LF 的跨车辆压力主要在传感器几何，而不是 L。

### 9.4 模型包

```text
topology, weights, bias, activation
input_order, scaler, units
quantization, schema_version, model_version, checksum
input_dim, output_dim, kappa_ref, alpha
```

运行时校验维度和 CRC；不匹配时只跑 PI。A/B 双槽、原子切换、回滚。

### 9.5 标定记录与上电自检（`nncar_calib`）

`firmware/core/include/nncar/calib.h` + `src/calib.c`。原则：**能自动标定的必须是“有可观测目标”的量；机械量靠人填**。

| 参数 | 归属 | 为什么 |
|---|---|---|
| 轮径、轮距 L、`sensor_to_axle`、传感器间距、PPR/减速比 | **手填 JSON** | 机械量，没有外部真值就无法分离“尺寸误差”和“打滑” |
| `motor.deadband` | 记录，可自动辨识 | 扫 PWM 看编码器是否起转，目标明确 |
| `motor.kff` | 记录，可自动辨识 | 稳态速度比 `v_actual / (u − deadband)` |
| `line.kappa_gain` | 记录，可在线微调 | 车上唯一可测的真值信号是质心偏移，稳态偏移→0 |
| 母线分压比 | 记录，只能测下陷 | 没有基准电压就没有绝对刻度 |
| `counts_per_meter` | 手填 | `ppr × gear × quad / (2πr)`，其中 r 不可自测 |

记录格式（固定容量、CRC、带来源）：

```c
typedef struct { uint8_t id; uint8_t source; float value; float quality; } nncar_calib_entry_t;
typedef struct {
    uint16_t version, count; uint32_t stamp_us; char vehicle_id[16];
    nncar_calib_entry_t entries[16]; uint32_t crc;
} nncar_calib_record_t;
```

四条硬规则（都在 `calib.c` 里，不是文档约定）：

1. `quality < 0.5` **拒绝写入**，不覆盖旧值——一次失败的标定不能进 flash。
2. `source == MANUAL` 的条目**拒绝被自动路径覆盖**。
3. `source == BENCH` 的条目**可以存、可以看，但既不参与 `verified()`，也不会被 `apply()` 采用**——仿真台架值不许悄悄驱动实车。
4. `apply()` 会**重新检查**范围（`deadband ∈ [0,0.3]`、`kff ∈ [0,2]`、`kappa_gain ∈ [0.5,4]`），因为记录来自 flash，属于不可信输入。

存储是两槽 vtable（`read/write` + `ctx`，MCU 用 flash 扇区，host 用文件或 RAM）：`save()` 写 `stamp_us & 1` 槽，`load()` 读两槽、各自验 CRC 和版本号，取更新的那个。一次写坏不会丢掉上一份。

`verified` 现在是**两个独立声明**，不再是一个手写 bool：

```text
nncar_profile_is_verified()   // 编译期：JSON 里人填的机械量可信
nncar_calib_verified(&rec)    // 运行期：三个可标定量齐全且质量达标、且非 BENCH
```

上电自检（`nncar_calib_selftest`，**不动车、不改参数**）只查三件事：母线在 `[rail_min_v, rail_max_v]` 内、温度低于 `temp_stop_c`、可用灰度通道数 ≥ `conf_valid_min`。灰度的对比度必须车动起来才能验，归到辨识层。

死区辨识做成**流式接口**，库本身从不驱动电机：标定模式（或台架）施加单调 `|pwm|` 斜坡，逐点喂 `(pwm, 实测速度)`，最后取“最后一个不动点”和“第一个动点”的中点；坡道没出现运动就返回 `false`（轮子卡住 / 编码器坏 / 时长不够）。

`kff` 同样流式：喂稳态点 `(实测速度, 指令 u, v_max_eff)`，做过原点最小二乘，`kff = 1 / 斜率`，`quality` 取该拟合的 R²。注意 `u` 是**补偿前**的指令，因为执行器补偿后等效 drive ≈ u；喂补偿后的 PWM 会把死区再算一遍。

闭环验证台架 `nncar_calib_bench`（ctest `calib_identify`）跑在同一个仿真 plant 上，真值已知，编码器按 `counts_per_meter` 量化、测速用窗口差分：

| case | 真值死区 | 摩擦 | 辨识死区 | 误差 | kff | 质量 |
|---|---|---|---|---|---|---|
| 0 | 0.050 | 0 | 0.055 | 0.005 | 0.9988 | 1.00 |
| 1 | 0.070 | 1e-4 N·m | 0.075 | **0.000** | 1.0067 | 1.00 |
| 2 | 0.100 | 0 | 0.105 | 0.005 | 0.9982 | 1.00 |

门槛：死区 ≤0.008、`kff` 偏离 1 ≤5%。三条要点：

1. 辨识出来的是**表观死区**。plant 里的 Coulomb 摩擦（`sim.motor_stiction_nm`，默认 0，取 0 时逐位不变）会把起转点抬高 `(1-db)·s/torque_gain`，case 1 的误差 0.000 就是对照这个表观值算的——这正是控制器该补偿的量。
2. `+0.005` 的固定偏差来自坡道步长 0.01 取中点；要更准就细化步长，代价是标定时间线性增长（当前 20 档 × 0.1 s ≈ 2 s/轮）。
3. **窗口 latch 必须在步进之前**。第一版在步进后取计数，窗口只覆盖 24 个 tick 却除以 25，`kff` 系统性偏低 4%（实测 1.036）；实车采样也有同样的坑。

## 11. MVP 与实现顺序

```text
MVP-0  schema / logger / replay / profile / golden log
        |
MVP-1  Gray PID + Motor PI + Mixer + Safety + 仿真
        |
Motor 台架辨识 + Residual NN（三档基线）
        |
LineFollower MLP vs PID（固定车、固定阵列，闭环 A/B）
        |
GRU / CfC（长时丢线、动态弯道、延迟补偿）
        |
Sensor Failure / DAgger / 跨车辆
```

- 每个阶段先写“淘汰门槛”；连续两轮无显著增益就回退传统方案。
- 当前状态：MVP-0、MVP-1 已完成；Motor 台架辨识链路（激励 -> CSV -> 辨识 -> 真值比对）已完成；四档基线（plain PI / PI+FF / PI+residual / NN direct）已在核心与对比工具中落地；residual 的教师数据、训练与权重导出链路已完成（教师为 H 步 MPC，不是 PI、也不是静态逆），闭环验收 gate 通过（held-out +15.6%、nominal +12.2%），C 侧已加载训练权重并由 `baseline_modes` 守住“≥10%”不变式；`NN direct` 已实测（nominal 与 residual 持平，母线下陷时稳态误差 3 倍、调节时间 31 倍，作为“原生替换”的对照保留，不作候选）。
- LineFollower 第一阶段不追求跨所有小车通用；先证明固定车、固定阵列下有闭环增量。
- LineFollower MLP vs PID 的闭环 A/B 已完成（§4.4）：单帧 MLP 在 8 个场景里 7 个更好（温和轨道 1.9–2.5 倍）、yaw 抖动小约 10 倍，但聚合只低 8.6%，且在 κ≈5.85 1/m 的急弯上差 56%，验收门槛 FAIL。追加的 70 维历史特征消融（§4.5）无增益并已回退；可观性分析显示历史在线性上只值约 5 个 R² 点。随后做了训练饱和度检查（§4.6）：epoch/容量/数据量/难样本加权四项全部饱和，证明不是训练不足；真正的缺口是逐样本 MSE 造成的幅值压缩（15–19%）。加入 profile 参数 `line.kappa_gain=1.8` 后，同一个网络聚合 RMS 0.0064 → 0.0022（比 PID 低 68.2%，仅比 GT oracle 高 12%），`nncar_line_ab --check` **判 PASS**。该增益本质是闭环回路刚度（教师有航向项、网络看不到 θ），必须在实车上重新标定后才能出货。
- 跨车辆 zero-shot 不在范围内；默认 few-shot 校准。
